# 合同发票统计

根据用户提供的已开发票和合同台账，登记发票并建立对应合同关系。由模型结合材料判断，使用环境已有的文档、文件和表格能力，不依赖自建程序或定时任务。

沿用已明确的律所名称、台账位置、字段和开票统计口径。操作飞书多维表格时使用可用的 lark-base 能力，读取合同与发票表的实际结构；不预设表名、字段名或关联形式。

## 处理要点

- 读取票号、日期、金额和交易双方，结合票面买卖方角色确认客户与律所；区分价税合计、不含税金额及税额，按目标字段填写。
- 用发票号码核对本批及目标台账，已有记录不重复新增。作废、红冲或更正票按票面状态及台账规则处理，规则不清时不按普通正数票累计。
- 结合合同号、客户名称与其他材料证据匹配合同。同一客户可能有多份合同，不能只凭同名或金额相近认定关系；候选无法区分时说明依据并请用户决定。
- 按实际表结构维护合同关联和已开票金额。公式或汇总字段由表自动计算，不手工重复累计；手工字段按已登记记录核对后更新。
- 如仅发票记录写入成功、合同关联或金额更新失败，查清实际状态后补做缺失部分，不再次新增发票或重复加金额。

## 任务边界示例

- ✓ "这几张销项发票登记并关联合同" → 本 skill
- ✓ "这张已经红冲的发票登记一下" → 本 skill，按票面状态和台账规则处理
- → "帮我把这张发票红冲掉" → 本 skill 不做实际红冲；红冲完成后再登记结果
- → "帮我给客户开张新发票" → 本 skill 不做实际开具，转用户
- → "报销贴票统计" → 转 legal-receipt

## 结果状态

- **成功**：发票记录写入 + 合同关联建立 + 已开票金额更新
- **挂起**：合同候选多于一个且无法唯一区分 → 列候选请用户裁决，不预选
- **部分成功**：主发票记录已写但合同关联或金额更新失败 → 复查当前记录后只补缺失部分，不重复新增或重复累加

## 交付边界

说明本次登记的发票及对应合同、已有记录、待确认关系和未完成操作，提供结果位置。仅在用户要求时整理相关文件；不自动扩展成合同登记、业务汇总或消息推送。
